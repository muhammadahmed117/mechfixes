================================================================================
1) APP KYA HAI?
================================================================================

Mechfixes aik multi-role app hai:

  1) CUSTOMER (User)  — masla bataye, AI se diagnosis le, qareebi mechanic dhunday
  2) MECHANIC         — shop profile banaye, customers se chat/reviews handle kare
  3) ADMIN            — mechanics approve/reject, users block, complaints manage

Tech stack:
  - Frontend: Flutter (Dart)
  - Backend Auth + Database: Firebase (Auth + Firestore)
  - AI Server: Python FastAPI (local PC pe chalta hai)
  - Maps: Google Maps + Directions API
  - Voice: speech_to_text + flutter_tts

2) APP START HONE KA FLOW (PIPELINE)
================================================================================

File: lib/main.dart

  Step 1: Flutter start → Firebase.initializeApp()
  Step 2: Language load (English / Roman Urdu SharedPreferences se)
  Step 3: home = AuthGate()

AuthGate (lib/core/navigation/auth_gate.dart) check karta hai:

  Agar user LOGIN NAHI:
      → WelcomeScreen (Get Started / Sign In)

  Agar user LOGIN HAI:
      → pehle check: admins/{uid} hai?
            HAAN → Admin Dashboard
      → warna check: users/{uid} hai?
            HAAN → Customer Home
      → warna check: mechanics/{uid} hai?

      → kuch bhi na mile → signOut → WelcomeScreen

Matlab: app band karke dubara open karo to session save rehti hai aur seedha
dashboard pe chali jati hai (Logout dabane pe hi login chahiye).

4) FIREBASE — FULL DETAIL
================================================================================

4.1) Firebase Auth
  - Email + password login/signup
  - Session device pe persist hoti hai
  - google_sign_in package pubspec mein hai, lekin main flow email/password hai

4.2) Firestore Collections

  -------------------- users/{uid} --------------------
  Customer profile
  Fields (examples):
    email, fullName, role, phone, status, isBlocked, adminNote, createdAt

  -------------------- mechanics/{uid} --------------------
  Mechanic shop profile
  Fields (examples):
    email, fullName, shopName, phone, address/location
    latitude, longitude, geoPoint
    specialties, selectedSkills
    isVerified, status (pending | approved | rejected)
    adminNote, isDemo
    rating, reviewCount
    openingDays, openingHours, imageUrl
    createdAt, updatedAt

  -------------------- admins/{uid} --------------------
  Sirf document exist karna = yeh user ADMIN hai
  (uid Firebase Auth user ki same honi chahiye)

  -------------------- reviews/{reviewId} --------------------
  Customer mechanic ko rating/review deta hai
  Mechanic rating/reviewCount update hota hai

  -------------------- complaints/{complaintId} --------------------
  Reports: userName, userEmail, mechanicName, issue, status (open/resolved)
  Admin resolve/reopen karta hai
  NOTE: Admin UI ready hai; customer-side "file complaint" form abhi app mein
        fully wired nahi (future ke liye rules create allow karti hain)

  -------------------- chats/{chatId}/messages/{messageId} --------------------
  Customer ↔ Mechanic chat
  chatId format: customerId__mechanicId
  participants array se access control


4.3) Firestore Rules (firestore.rules) — security

  function isAdmin():
    request.auth != null AND admins/{uid} document exists

  Mechanics:
    - Owner apna profile create/update/delete kar sakta hai
    - Rating/reviewCount update allowed (reviews ke liye)
    - Admin sirf yeh fields change kar sakta hai:
        status, isVerified, adminNote, updatedAt

  Users:
    - Self read/write
    - Admin sirf: status, isBlocked, adminNote, updatedAt
    - Delete nahi

  Complaints:
    - Auth user create/read
    - Admin update limited fields (status, resolvedAt, adminNote, updatedAt)

  Chats:
    - Sirf participants read/write kar sakte hain

Yeh soft-status model hai: Auth account delete nahi hota; status se control.

8) AI BACKEND (FastAPI) — FULL PIPELINE
================================================================================

Folder: ai_backend/

Files:
  main.py          → FastAPI routes
  config.py        → model paths, Groq settings
  train_model.py   → ML + RAG artifacts train
  .env             → GROQ_API_KEY etc. (local secret)
  start_server.bat → uvicorn start

Server:
  uvicorn → http://0.0.0.0:8000

APIs:
  GET  /health
  POST /api/diagnose
       body: { "symptoms": "engine overheating..." }
       response:
         predicted_fault
         ai_advice_english
         ai_advice_roman_urdu

Working pipeline:
  1) Flutter symptoms bhejta hai HTTP POST se
  2) Backend sklearn model se fault predict
  3) RAG (FAISS) + Groq LLM se bilingual advice
  4) Flutter UI pe English + Roman Urdu dikhata hai

Flutter URL config:
  lib/core/config/diagnostic_api_config.dart

  Emulator debug:  http://10.0.2.2:8000/api/diagnose
  Real phone APK:  http://YOUR_PC_LAN_IP:8000/api/diagnose
                   (pcLanIp config mein set karo, e.g. 192.168.x.x)
  Override:        --dart-define=DIAGNOSE_URL=...

Zaroori:
  - PC aur phone same WiFi
  - FastAPI server chal raha ho
  - Android cleartext traffic allowed (AndroidManifest)
